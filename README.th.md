# TESR ROI Studio + Vision Runner

*English version: [README.en.md](README.en.md) · [กลับไปหน้าหลักของ repo](README.md)*

**เปิดใช้งานเครื่องมือ: https://tesr-channel.github.io/AI_ROI_Designer/**

เครื่องมือ 2 ชิ้นที่ทำงานคู่กัน สำหรับงาน AI Vision บน Edge Device

| ไฟล์ | หน้าที่ | ใช้ที่ไหน |
|---|---|---|
| `index.html` | หน้าเว็บสำหรับ **ตีกรอบ ROI หลายจุดต่อกล้อง** เลือก task/model ต่อกรอบ ทดลองอ่านค่าในเบราว์เซอร์ แล้วส่งออกเป็น config + Python | เปิดด้วยเบราว์เซอร์เครื่องไหนก็ได้ ไม่ต้องติดตั้ง ไม่ต้องต่อเน็ต |
| `tesr_line_engine.py` | เอนจินสำหรับเส้นและพื้นที่: วัดระดับ วัดขนาด นับข้ามเส้น นับในพื้นที่ | วางข้าง ๆ runner |
| `tesr_vision_runner.py` | อ่าน config แล้วประมวลผลจริงจากกล้อง/วิดีโอ/ภาพ พร้อมส่งค่าออก CSV / JSONL / MQTT / Webhook | Windows, macOS, Linux, Raspberry Pi, Jetson, Mini PC |

แนวคิด: **ตีกรอบครั้งเดียว → ได้ไฟล์ config → เอาไปรันเครื่องไหนก็ได้ ผลลัพธ์เหมือนกัน**

หน้าเว็บมีทั้ง **ภาษาไทยและอังกฤษ** สลับได้ที่ปุ่ม TH / EN มุมบน ระบบจะจำภาษาที่เลือกไว้ในเครื่องนั้น
config และ Python ที่ส่งออกเหมือนกันทุกประการไม่ว่าจะเลือกภาษาใด

หน้าเว็บมี 3 โหมดการทำงาน

| โหมด | ใช้ตอนไหน |
|---|---|
| **ภาพนิ่ง** | ตีกรอบบนรูปที่ถ่ายมาจากหน้างาน แม่นยำที่สุดเพราะภาพไม่ขยับ |
| **กล้องสด** | เห็นภาพจากกล้องจริง ๆ ตรงกลางจอ พร้อมค่าที่อ่านได้เกาะอยู่บนกรอบแบบเรียลไทม์ ใช้ตอนจัดมุมกล้องหน้างาน |
| **จับเป็นภาพนิ่ง** | อยู่ในโหมดกล้องสด พอได้มุมที่พอใจก็กดปุ่มเดียว กลายเป็นภาพอ้างอิงให้ตีกรอบละเอียดต่อ |

ส่วนงานตีกรอบ อ่านตัวเลข ตรวจสี ตรวจการเปลี่ยนแปลง และ QR ทำงานออฟไลน์ทั้งหมด

## 1. Workflow

```text
ถ่ายภาพหน้างาน
  → เปิด index.html แล้วลากกรอบ ROI (ได้หลายกรอบ หลายกล้อง)
  → เลือก task ของแต่ละกรอบ (อ่านตัวเลข / OCR / YOLO / QR / ตรวจสี / ตรวจการเปลี่ยนแปลง)
  → ทดลองอ่านค่าในเบราว์เซอร์เพื่อจูนพารามิเตอร์คร่าว ๆ
  → ส่งออก config.json + tesr_vision_runner.py
  → ทดสอบกับภาพนิ่ง (--once)
  → ทดสอบหน้างานแบบเห็นภาพสด (--test) และจูนด้วยแถบเลื่อน (--calibrate)
  → รันจริงแบบไม่มีจอ (--headless) แล้วส่งค่าเข้าระบบ (MQTT / Node-RED / Database / Dashboard)
```

## 1.5 ใช้โมเดลที่เทรนเองแล้ว

กด **+ เพิ่มโมเดลที่เทรนแล้ว** ในแผงซ้าย เลือกไฟล์ `.onnx` ใส่ชื่อคลาส แล้วเลือกโมเดลนั้นให้กรอบใด ๆ ที่เป็น task YOLO
กด **ทดสอบเลย** จะเห็นกล่องผลลัพธ์วาดทับบนภาพทันที ในโหมดกล้องสดจะรันต่อเนื่องให้เลย

export โมเดลจาก Ultralytics แบบนี้

```bash
yolo export model=best.pt format=onnx opset=12
```

* โมเดลเก็บอยู่ในเบราว์เซอร์เครื่องนี้เท่านั้น ไม่มีการอัปโหลดไปที่ไหน
* ตอน export config ระบบจะใส่ชื่อไฟล์โมเดลกับรายชื่อคลาสลงใน config ให้ แต่ไฟล์ `.onnx` ต้องคัดลอกไปวางข้าง ๆ `tesr_vision_runner.py` เอง
* ฝั่ง Python รัน `.onnx` ด้วย `onnxruntime` อย่างเดียว **ไม่ต้องลง Ultralytics หรือ PyTorch** ซึ่งสำคัญมากบน Raspberry Pi

```bash
pip install onnxruntime          # ประมาณ 50 MB เทียบกับ ultralytics+torch ที่เกิน 2 GB
```

การเตรียมภาพ (letterbox) และการถอดผลลัพธ์ (NMS) ของฝั่งเบราว์เซอร์กับฝั่ง Python เขียนให้ตรงกันและทดสอบเทียบกันแล้วว่าได้กล่องและค่าความมั่นใจชุดเดียวกัน สิ่งที่เห็นในเบราว์เซอร์จึงเป็นสิ่งที่จะได้บนเครื่องจริง

## 2. Task ที่รองรับต่อ 1 กรอบ

| task | ใช้ทำอะไร | ต้องมีโมเดลไหม |
|---|---|---|
| `digits_7seg` | อ่านตัวเลขจากจอเครื่องจักร 7-segment / LED / LCD | ไม่ต้อง (OpenCV ล้วน) |
| `ocr_text` | อ่านข้อความ/ตัวเลขทั่วไป | Python ใช้ pytesseract หรือ easyocr · ในเบราว์เซอร์ใช้ Tesseract.js (ต่อเน็ตครั้งแรก) |
| `plate_ocr` | อ่านป้ายทะเบียน พร้อมตรวจรูปแบบป้าย | ใช้เอนจิน OCR ชุดเดียวกับ `ocr_text` |
| `yolo_detect` | ตรวจจับวัตถุในกรอบ นับจำนวน หรือส่งรายละเอียด | ไฟล์ `.pt` ของคุณเอง |
| `yolo_classify` | จำแนกภาพในกรอบ เช่น OK / NG | ไฟล์ `.pt` ของคุณเอง |
| `barcode_qr` | อ่าน QR และบาร์โค้ดแท่ง | ไม่ต้อง · ตัวถอดรหัสฝังมาให้แล้วทั้งสองฝั่ง |
| `presence_diff` | ตรวจว่ามีของ/มีการเปลี่ยนแปลงในกรอบ | ไม่ต้อง |
| `color_check` | ตรวจไฟสถานะ ไฟหอคอย สีชิ้นงาน | ไม่ต้อง |

แต่ละกรอบมี `output_key` ของตัวเอง จึงส่งค่าออกได้พร้อมกันหลายค่าในเฟรมเดียว

## 3. ติดตั้ง

```bash
python -m pip install --upgrade pip
python -m pip install opencv-python numpy
```

ติดตั้งเพิ่มเฉพาะที่ใช้ (ดู `requirements.txt`)

```bash
pip install ultralytics     # ถ้ามี ROI ที่ใช้ YOLO
pip install pytesseract     # ถ้ามี ROI ที่ใช้ OCR (ต้องลง Tesseract engine ของ OS ด้วย)
pip install paho-mqtt       # ถ้าจะส่งค่าเข้า MQTT / Node-RED
```

หมายเหตุตามแพลตฟอร์ม

* **Raspberry Pi** — `sudo apt install python3-opencv` เร็วกว่าการ build จาก pip มาก
* **Jetson (JetPack)** — OpenCV มากับ JetPack อยู่แล้ว อย่าลง `opencv-python` ทับ ให้ใช้ของระบบ
* **macOS** — หน้าต่างภาพต้องรันจาก Terminal ปกติ และอนุญาต Camera ใน System Settings → Privacy
* **Windows** — ถ้ากล้องเปิดช้า โปรแกรมเลือก DirectShow ให้อัตโนมัติแล้ว

## 6. ผลลัพธ์ที่ส่งออก

* หน้าจอ (console)
* `logs/results.csv` — timestamp, camera, roi, key, value, conf
* `logs/results.jsonl` — 1 บรรทัด 1 เหตุการณ์ เหมาะกับการนำเข้า database
* MQTT — topic `<prefix>/<camera_id>/<output_key>` payload เป็น JSON ต่อเข้า Node-RED ได้ทันที
* Webhook — HTTP POST เมื่อค่าเปลี่ยน (ใช้ urllib ใน Python มาตรฐาน ไม่ต้องลงเพิ่ม)
* ภาพ snapshot เมื่อค่าเปลี่ยน (เปิดใน Runtime)

ระบบจะส่งค่าออกก็ต่อเมื่ออ่านได้ค่าเดิมซ้ำครบตาม `stable_frames` เพื่อกันค่ากระพริบตอนตัวเลขกำลังเปลี่ยน

## 6.3 การอ่าน QR และบาร์โค้ด

ใช้งานได้ทันทีทั้งสองฝั่ง **ไม่ต้องติดตั้งอะไรเพิ่ม และไม่ต้องต่ออินเทอร์เน็ต**

| | ในเบราว์เซอร์ | ใน Python |
|---|---|---|
| QR | BarcodeDetector ถ้ามี ไม่มีก็ใช้ตัวถอดที่ฝังในไฟล์ | OpenCV QRCodeDetector |
| Code 128 · Code 39 · ITF | ตัวถอดที่ฝังในไฟล์ | ตัวถอดที่เขียนไว้ใน runner |
| EAN-13 · UPC-A · EAN-8 | ตัวถอดที่ฝังในไฟล์ | OpenCV barcode detector แล้วค่อยตกมาที่ตัวถอดใน runner |

เดิมฝั่ง Python ต้องลง `pyzbar` (ซึ่งต้องลง `libzbar0` ของระบบด้วย) ตอนนี้ **ไม่ต้องแล้ว**
โค้ดถอดรหัสเขียนไว้ในไฟล์ runner โดยตรง ถ้าเครื่องไหนมี `pyzbar` อยู่แล้วก็ยังใช้เป็นตัวสำรองได้

**วิธีอ่านให้ติดง่าย**

* วางกรอบให้คลุมบาร์โค้ดทั้งอัน **รวมขอบขาวซ้ายขวา** อย่างน้อยข้างละประมาณ 10 เท่าของความกว้างแท่งบางที่สุด
* วางให้แท่งตั้งตรง เอียงได้ราว 8° ถ้าเอียงมากกว่านั้นให้หมุนภาพด้วยช่อง "หมุนภาพก่อนประมวลผล"
* ป้ายกลับสี (แท่งขาวบนพื้นดำ) อ่านได้ ไม่ต้องตั้งค่าอะไรเพิ่ม
* ทุกฟอร์แมตตรวจ checksum และต้องมีอย่างน้อย 2 เส้นสแกนที่อ่านได้ตรงกันจึงจะตอบ ผลคือระบบจะ**อ่านไม่เจอ**มากกว่า**อ่านผิด** ซึ่งเป็นพฤติกรรมที่ปลอดภัยกว่าสำหรับงานโรงงาน

## 6.4 ปุ่ม "ทดสอบเลย"

อยู่ในแผง **ทดลองอ่านในเบราว์เซอร์** ทางขวา ใช้ได้กับทุก task

| task | ทำงานในเบราว์เซอร์ด้วยอะไร | ต้องต่อเน็ตไหม |
|---|---|---|
| อ่านตัวเลข 7-segment | JavaScript ที่พอร์ตมาจาก Python ตรง ๆ | ไม่ต้อง · อ่านใหม่ทันทีทุกครั้งที่แก้ค่า |
| ตรวจสี / ตรวจการเปลี่ยนแปลง | JavaScript | ไม่ต้อง |
| Barcode / QR | ตัวถอดรหัสที่ฝังอยู่ในไฟล์ HTML | ไม่ต้อง · ทุกเบราว์เซอร์ |
| OCR ข้อความ | Tesseract.js | ต่อเน็ตครั้งแรกเพื่อโหลดเอนจินและไฟล์ภาษา |
| YOLO detect / classify | onnxruntime-web | ต่อเน็ตครั้งแรกเพื่อโหลดเอนจิน |

ถ้าเอนจินโหลดไม่ได้ ระบบจะขึ้นข้อความบอกตรง ๆ ภายใน 20 วินาที ไม่ค้างรอไปเรื่อย ๆ

## 6.5 เมื่ออ่านค่าไม่แม่น ให้กด "ปรับอัตโนมัติ"

เลือกกรอบที่เป็น task อ่านตัวเลข แล้วดูแผง **ตรวจสอบความแม่นยำ** ทางขวา

**ปุ่มปรับอัตโนมัติ** จะไล่ค่าทุกชุดที่เป็นไปได้ (วิธี threshold, ขั้วสว่าง/มืด, blur, min_fill) แล้วเลือกชุดที่ดีที่สุดให้
สิ่งที่ต่างจากการไล่ค่าธรรมดาคือ มันไม่ได้เลือกชุดที่ "อ่านถูกครั้งเดียว" แต่เลือกชุดที่ **อ่านได้ค่าเดิมต่อเนื่องในช่วงกว้างที่สุด**
เพราะค่าที่อ่านถูกแบบฉิวเฉียดจะพลิกทันทีที่แสงเปลี่ยนนิดเดียว

ตัวเลข **band** ที่แสดงคือความกว้างของช่วงปลอดภัยนั้น

| band | ความหมาย | ควรทำอะไรต่อ |
|---|---|---|
| ≥ 0.16 | กว้าง ทนแสงเปลี่ยนได้ดี | ใช้งานได้ ตั้ง stable_frames 2 ก็พอ |
| 0.08 – 0.16 | พอใช้ | ตั้ง stable_frames 3 ขึ้นไป และทดสอบซ้ำในช่วงเวลาที่แสงต่างกัน |
| < 0.08 | แคบ เสี่ยงพลิกค่า | อย่าเพิ่งใช้งานจริง แก้ที่หน้างานก่อน |
| ไม่สำเร็จ | ภาพนี้อ่านไม่ได้เลย | ต้องแก้แสง/มุมกล้อง/ระยะ ก่อนเท่านั้น ปรับซอฟต์แวร์ไม่ช่วย |

**ค่าเริ่มต้นของกรอบใหม่คือ 1 หลัก** เพราะกรอบละหลักคือวิธีที่ทนแสงและมุมกล้องได้ดีที่สุด
แต่ละหลักมีพารามิเตอร์ของตัวเอง หลักที่โดนแสงสะท้อนจึงจูนแยกได้โดยไม่กระทบหลักอื่น
ถ้าอยากอ่านทั้งชุดในกรอบเดียว ให้ตั้ง "จำนวนหลักในกรอบนี้" เป็นจำนวนจริง เช่น 4
ถ้าตั้งไม่ตรง ระบบจะบอกให้เองว่าในกรอบมีกี่หลัก

**ปุ่มตรวจอย่างเดียว** จะบอกสาเหตุเป็นข้อ ๆ พร้อมวิธีแก้ เช่น กรอบเล็กเกินไป ภาพสว่างจนล้น คอนทราสต์ต่ำ
หรือจำนวนกลุ่มตัวเลขที่ตรวจพบไม่ตรงกับที่ตั้งไว้

**ลำดับการแก้ที่ได้ผลจริง เรียงจากได้ผลมากไปน้อย**

1. **แสง** — แสงสะท้อนบนกระจกหน้าจอคือสาเหตุอันดับหนึ่ง เอียงกล้อง 10–20° ให้พ้นมุมสะท้อน ใส่ฮูดบัง
2. **ขนาด** — ตัวเลขควรสูงอย่างน้อย 40 px ในกรอบ ถ้าไม่ถึงให้ขยับกล้องเข้าใกล้ ไม่ใช่ไปซูมดิจิทัลทีหลัง
3. **exposure ของกล้อง** — ถ้าภาพล้นขาว ข้อมูลหายถาวร กู้ด้วยซอฟต์แวร์ไม่ได้ ต้องลดที่กล้อง
4. **กรอบ** — ครอบเฉพาะตัวเลข เผื่อขอบนิดเดียว อย่ากินขอบจอหรือสัญลักษณ์อื่นเข้ามา
5. **ตั้งจำนวนหลักให้ตรง** — ช่วยให้ระบบตัดผลที่แบ่งหลักผิดทิ้งได้
6. **แล้วค่อยกดปรับอัตโนมัติ**

## 6.6 อ่านหลายกรอบให้เห็นครบในบรรทัดเดียว และรวมเป็นตัวเลขชุดเดียว

เวลาแบ่งกรอบละหลัก จะได้ ROI จำนวนมาก เดิม console จะพิมพ์ทีละกรอบตอนที่ค่าเปลี่ยน
ทำให้อ่านยากและเรียงสลับกันไปมา ตอนนี้ค่าเริ่มต้นเปลี่ยนเป็น **พิมพ์บรรทัดเดียวที่มีครบทุกค่า**

```
2026-07-29T00:50:19  meter_top=225466  meter_bottom=6987  digits_1=2  digits_2=2  digits_3=5 ...
```

| คำสั่ง | ผล |
|---|---|
| `--console summary` | ค่าเริ่มต้น · หนึ่งบรรทัดครบทุกค่า พิมพ์เมื่อมีอะไรเปลี่ยน |
| `--console summary --every 1` | พิมพ์ทุก 1 วินาที ไม่ว่าจะเปลี่ยนหรือไม่ เหมาะกับการเฝ้าดูหน้างาน |
| `--console change` | แบบเดิม คือหนึ่งบรรทัดต่อกรอบตอนค่าเปลี่ยน |
| `--console none` | เงียบ เหมาะกับตอนรันเป็น service |

### รวมกรอบละหลักให้เป็นตัวเลขชุดเดียว

มีสองวิธี

**วิธีที่ 1 — ตั้งในหน้าเว็บ** ใส่ชื่อกลุ่มเหมือนกันในช่อง **กลุ่ม** ของแต่ละกรอบ เช่น `meter_top`
กรอบที่ชื่อกลุ่มตรงกันจะถูกต่อกันเป็นค่าเดียว **เรียงจากซ้ายไปขวาให้อัตโนมัติ** ไม่ต้องกังวลลำดับตอนวาด

**วิธีที่ 2 — ให้โปรแกรมเดาให้** ใส่ `--auto-group` ตอนรัน ระบบจะจับกรอบอ่านตัวเลขที่อยู่แถวเดียวกัน
มารวมเป็นชุดเดียว ตั้งชื่อเป็น `row1`, `row2` ตามลำดับจากบนลงล่าง

```bash
python tesr_vision_runner.py --config config.json --auto-group --test
```

ถ้าโปรแกรมเห็นว่ามีกรอบที่น่าจะรวมกันได้แต่ยังไม่ได้เปิดใช้ จะขึ้นข้อความบอกให้เองตอนเริ่ม

ค่ากลุ่มจะถูกส่งออกไปทุกช่องทางเหมือนค่าอื่น ทั้ง console, CSV, JSONL, MQTT และ Webhook
โดยใช้ชื่อกลุ่มเป็น key ตรง ๆ

**สำคัญ**: ถ้ามีหลักใดอ่านไม่ออก ค่ากลุ่มจะแสดงเป็น `2?5466` และ**จะไม่ถูกส่งออก** จนกว่าจะอ่านได้ครบทุกหลัก
เพราะตัวเลขที่ขาดไปหนึ่งหลักคือตัวเลขที่ผิด ไม่ใช่ตัวเลขที่ใช้ได้บางส่วน

### หน้าจอแสดงผล

เดิมป้ายชื่อกรอบวางทับกันจนอ่านไม่ออกเมื่อกรอบอยู่ติดกัน ตอนนี้

* **ค่าที่อ่านได้แสดงอยู่กลางกรอบ** ไม่ล้นไปทับกรอบข้าง ๆ
* มุมกรอบมีเลขลำดับกำกับ
* **แถบสรุปผลอยู่ใต้ภาพ** ไม่ได้ทับบนภาพ จึงไม่มีทางบังจอเครื่องจักร แสดงตัวเลขชุดรวมตัวใหญ่
  แล้วตามด้วยรายการทุกกรอบพร้อมค่าและ conf
* ตัวเลขชุดรวมเป็นสีทองเมื่ออ่านครบ และเป็นสีแดงเมื่อมีหลักที่อ่านไม่ออก มองผ่าน ๆ ก็รู้
* กด `p` เพื่อซ่อนหรือแสดงแถบสรุป

## 6.7 เส้นและพื้นที่ — นับคน นับรถ วัดระดับ วัดขนาด

กรอบสี่เหลี่ยมตอบโจทย์ "อ่านค่าตรงนี้" แต่ตอบไม่ได้ว่า "มีคนเดินข้ามเส้นนี้กี่คน"
จึงเพิ่มรูปทรงอีกสองแบบ

| รูปทรง | Task | ใช้ทำอะไร | ต้องมีโมเดลไหม |
|---|---|---|---|
| เส้น | `level_line` | วัดระดับน้ำในถัง ไซโล หรือหลอดวัดระดับ | ไม่ต้อง |
| เส้น | `measure_line` | วัดขนาดชิ้นงาน ความกว้าง ระยะห่าง | ไม่ต้อง |
| เส้น | `line_count` | นับคนเข้าออก นับรถ นับชิ้นงานบนสายพาน แยกทิศทาง | ต้องมี |
| พื้นที่ | `zone_count` | นับจำนวนที่อยู่ในพื้นที่ ณ ขณะนั้น | ต้องมี |

### วัดระดับ

ลากเส้นจาก **A = ระดับต่ำสุด** ไปยัง **B = ระดับสูงสุด** ระบบหาผิวของเหลวจากรอยต่อความสว่างที่ชัดที่สุดบนเส้น
ใส่ `ค่าที่จุด A` และ `ค่าที่จุด B` เพื่อให้ผลออกมาเป็นหน่วยจริง เช่น 0–1000 ลิตร แทนที่จะเป็นเปอร์เซ็นต์

ทดสอบกับถังจำลองที่รู้ระดับแน่นอน: คลาดเคลื่อนสูงสุด **0.2%** ของความสูงเส้น

### วัดขนาด

ลากเส้นให้ตัดผ่านชิ้นงานจนสุด ปลายทั้งสองข้างต้องอยู่บนพื้นหลัง ระบบวัดระยะระหว่างขอบแรกกับขอบสุดท้าย

ถ้าอยากได้เป็นมิลลิเมตรแทนพิกเซล ต้องตั้ง **สเกลของกล้อง** ก่อน — กดปุ่ม "ลากเส้นอ้างอิง"
แล้วลากทับวัตถุที่รู้ขนาดจริง จากนั้นใส่ความยาวจริงลงไป

ทดสอบกับชิ้นงานที่รู้ขนาดแน่นอน: คลาดเคลื่อน **0.26 px** และหลังคาลิเบรต **0.07 มม. จาก 30 มม.**

> ข้อควรระวังที่ต้องบอกลูกค้าตรง ๆ: ตัวเลขข้างต้นวัดจากภาพสังเคราะห์ที่ควบคุมได้ทุกอย่าง
> หน้างานจริงมี perspective มีเลนส์บิดเบี้ยว มีชิ้นงานที่ไม่ได้วางระนาบเดียวกับเส้นอ้างอิง
> ความแม่นยำจริงต้องวัดกับชิ้นงานมาตรฐานที่หน้างานเท่านั้น และควรวางกล้องให้ตั้งฉากกับระนาบที่วัดมากที่สุด

### วิธีวัดขนาดทีละขั้น

**1. ตั้งสเกลของกล้องก่อน** (ทำครั้งเดียวต่อการติดตั้งกล้อง)

หาอะไรก็ได้ที่รู้ขนาดจริงแน่นอนวางในระนาบเดียวกับชิ้นงาน เช่นตลับเมตรหรือเกจ
กด **ลากเส้นอ้างอิง** แล้วลากทับระยะที่รู้ค่า เช่นลากจากขีด 0 ถึงขีด 10 ซม.
จากนั้นใส่ `100` ในช่องความยาวจริง และ `mm` ในช่องหน่วย

ยิ่งลากยาว ยิ่งแม่น ลากทับ 10 ซม. แม่นกว่าลากทับ 1 ซม. มาก

**2. ลากเส้นวัด ให้ตัดผ่านชิ้นงานจนสุด**

จุดสำคัญที่คนพลาดบ่อยที่สุด: **ปลายเส้นทั้งสองข้างต้องอยู่บนพื้นหลัง ไม่ใช่บนชิ้นงาน**

```
ถูก:   ────┤████████████├────      ปลายเส้นอยู่นอกชิ้นงานทั้งสองข้าง
ผิด:       ├──████████──┤          เส้นสั้นเกิน จบอยู่บนชิ้นงาน
```

ระบบหาขอบแรกกับขอบสุดท้ายบนเส้น แล้ววัดระยะระหว่างสองขอบนั้น
ถ้าปลายเส้นอยู่บนชิ้นงาน จะไม่มีขอบให้เจอ

**3. ดูผลในแผงขวา**

แถบภาพบนคือพิกเซลที่เส้นสแกนผ่านจริง ๆ ยืดตรงให้ดูง่าย
กราฟล่างคือความสว่างตลอดเส้น **เส้นแดงสองเส้นคือขอบที่ระบบเจอ**

ถ้าเส้นแดงไปเกาะผิดที่ ก็เห็นได้ทันทีว่าผิดตรงไหน ไม่ต้องเดา

### วัดระยะระหว่างขีด เช่น จาก 6 ถึง 7 ซม.

โหมด **ขอบนอกสุด** ออกแบบมาสำหรับวัดชิ้นงานที่เป็นก้อนตัน มันหาขอบแรกกับขอบสุดท้ายแล้ววัดระหว่างนั้น
ถ้าเอามาวัดระหว่างขีดบนไม้บรรทัด จะไม่ทำงาน เพราะช่องว่างระหว่างขีดหน้าตาเหมือนพื้นหลังทุกอย่าง

ให้เปลี่ยนโหมดเป็น **ระหว่างขีด (กึ่งกลางถึงกึ่งกลาง)** ซึ่งหา*กึ่งกลาง*ของขีดแต่ละขีด
แล้ววัดจากกึ่งกลางขีดแรกถึงกึ่งกลางขีดสุดท้าย ตรงกับที่คนอ่านไม้บรรทัดหมายถึงเวลาพูดว่า "จาก 6 ถึง 7"

**ขั้นตอน**

1. ตั้งสเกลก่อน ลากเส้นอ้างอิงให้**ยาวที่สุดเท่าที่ทำได้** เช่นครอบ 3 ซม. ขึ้นไป แล้วใส่ค่าจริง
   (ถ้าตั้งสเกลครอบ 6→7 พอดี แล้ววัด 6→7 จะได้ 10 มม. เสมอ เพราะเป็นการวัดตัวเอง ไม่ใช่การทดสอบ)
2. ลากเส้นวัดให้**ผ่านขีดทั้งสอง** และอยู่ในระดับความสูงที่ขีดยาวถึงจริง ๆ
3. เปลี่ยนโหมดเป็น **ระหว่างขีด**
4. ดูกราฟด้านล่าง เส้นทองบาง ๆ คือขีดทุกขีดที่เจอ เส้นแดงสองเส้นคือขีดหัวท้ายที่ใช้วัด

**ความแม่นยำที่วัดได้** จากไม้บรรทัดสังเคราะห์ 41 px/มม. ตั้งสเกลครอบ 20 มม. แล้ววัดช่วงอื่นเป็นการทดสอบอิสระ

| วัด | ได้ | คลาดเคลื่อน |
|---|---|---|
| 1 มม. | 0.99 | 0.01 มม. |
| 5 มม. | 4.98 | 0.02 มม. |
| 10 มม. | 10.00 | 0.00 มม. |
| 30 มม. | 30.00 | 0.00 มม. |

ตัวเลขนี้มาจากภาพสังเคราะห์ที่ควบคุมได้ทุกอย่าง ของจริงจะแย่กว่านี้ตามคุณภาพกล้อง เลนส์ และมุมกล้อง

ยาวที่สุดเท่าที่ทำได้ ความคลาดเคลื่อนตอนลากเส้นอ้างอิงด้วยมือ (สัก 2-3 พิกเซล) จะถูกหารด้วยความยาวเส้น
ยิ่งเส้นยาว ผลกระทบยิ่งเล็ก

ทดสอบโดยจงใจวางปลายเส้นอ้างอิงพลาดไป 3 พิกเซล แล้ววัดระยะจริง 10.000 มม.

| เส้นอ้างอิงครอบ | อ่านได้ | คลาดเคลื่อน |
|---|---|---|
| 5 มม. | 9.854 | −0.146 มม. |
| 10 มม. | 9.926 | −0.074 มม. |
| 20 มม. | 9.962 | −0.038 มม. |

**กฎง่าย ๆ**: ลากเส้นอ้างอิงให้ยาวอย่างน้อย 1 ใน 3 ของความกว้างภาพ และอย่าตั้งสเกลบนช่วงเดียวกับที่จะวัด
เพราะจะได้ค่าถูกเสมอโดยไม่ได้พิสูจน์อะไร

### จะรู้ได้ยังไงว่าผลถูก

1. **นับจำนวนขีด** ใต้ค่าที่อ่านได้จะบอกว่าเจอกี่ขีด วัด 6→7 ซม. บนไม้บรรทัดที่มีขีดมิลลิเมตร ต้องได้ 11 ขีด
   (11 ขีด = 10 ช่อง = 10 มม.) ถ้าได้ 12 แปลว่าเส้นเลยไปโดนขีดถัดไป
2. **ดูเส้นแดงในกราฟ** ต้องเกาะอยู่บนขีด 6 และขีด 7 พอดี
3. **วัดช่วงที่รู้คำตอบอยู่แล้ว** ตั้งสเกลครอบ 3 ซม. แล้ววัด 1 ซม. ถ้าได้ 10.0 มม. แปลว่าใช้ได้

---

**ตรวจคำตอบด้วยตัวเลข 2 ตัวที่แสดงใต้ค่า**

ใต้ค่าที่อ่านได้จะมี **จำนวนขีด** และ **ระยะต่อช่อง** ใช้ตรวจได้ทันที

* วัด 6→7 ซม. บนไม้บรรทัดมิลลิเมตร ต้องได้ **11 ขีด** และ **1.00 มม. ต่อช่อง**
* ถ้าได้ 10 ขีด แปลว่าเส้นพลาดขีดปลายไปหนึ่งขีด ค่าที่ได้จะเป็น 9 มม. ซึ่ง**ผิดโดยไม่มีคำเตือน**
  เพราะระยะต่อช่องยังเป็น 1.00 อยู่ดี — จำนวนขีดคือตัวเดียวที่จับได้

**ระดับความสูงของเส้นสำคัญมาก** ต้องลากให้อยู่ในช่วงที่ขีดยาวถึงจริง ๆ
ถ้าลากสูงไปจะโดนแค่ปลายขีดหรือไม่โดนเลย ถ้าต่ำไปจะหลุดออกนอกแถบวัด
ทดสอบกับภาพจริงจากหน้าจอของคุณ: ที่ความสูงพอดีได้ 11 ขีด แต่สูงขึ้นไปแค่ 8 พิกเซลเหลือ 10 ขีด

### ไม่ต้องเดาค่าเอง — กดปุ่มปรับอัตโนมัติ

เลือกกรอบที่เป็นเส้นวัด แล้วดูแผง **ตรวจสอบความแม่นยำ** ทางขวา (แผงเดียวกับที่ใช้กับการอ่านตัวเลข)

**ปรับอัตโนมัติ** จะไล่ค่าทั้งสามตัว — ความหนาเส้นสแกน, Smooth, คอนทราสต์ขั้นต่ำ — รวม 160 ชุด
แล้วเลือกชุดที่ **อ่านได้ค่าเดิมต่อเนื่องในช่วงกว้างที่สุด** ไม่ใช่ชุดที่บังเอิญอ่านถูกครั้งเดียว

สำหรับโหมด "ระหว่างขีด" มีหลักฐานเพิ่มอีกอย่าง: ไม้บรรทัดจริงมีขีดห่างเท่า ๆ กัน
ระบบจึงให้คะแนนความสม่ำเสมอของระยะห่างด้วย ชุดค่าที่ไปเจอจุดมั่ว ๆ สองจุดจะแพ้แถวขีดที่เรียงสวย

**ถ้าหาไม่เจอ ระบบจะบอกตรง ๆ** ว่าเส้นน่าจะไม่ได้ตัดผ่านขีดจริง แทนที่จะคายตัวเลขมั่ว
และถ้าได้ผลแต่ระยะห่างขีดไม่สม่ำเสมอเกิน 15% จะขึ้นเตือนว่ายังไม่น่าเชื่อถือ

ทดสอบกับภาพไม้บรรทัดจริงจากหน้าจอผู้ใช้ 6 กรณี ปรับอัตโนมัติได้ค่าถูก 5 กรณี
กรณีที่พลาดคือเส้นลากต่ำจนหลุดขอบแถบวัดที่ปลายข้างหนึ่ง ซึ่งมองเห็นได้จากเส้นแดงในกราฟทันที

**ค่าเริ่มต้นก็ปรับใหม่แล้ว** จากการทดสอบกับภาพจริง เป็น Smooth 3 และคอนทราสต์ขั้นต่ำ 20
ซึ่งใช้ได้เลยในหลายกรณีโดยไม่ต้องปรับอะไร

### นับข้ามเส้น

ลากเส้นขวางทางเดิน **ลูกศรสีทองบนเส้นคือทิศที่นับเป็น "เข้า"** สิ่งที่เห็นคือสิ่งที่นับ
ถ้าอยากสลับทิศ ไม่ต้องลากใหม่ ให้ตั้ง `invert` เป็นใช่

การนับต้องใช้โมเดลตรวจจับ เลือกได้ที่แผง **โมเดลตรวจจับของกล้องนี้** ทางซ้าย
โมเดลจะรันครั้งเดียวต่อเฟรมแล้วแบ่งผลให้ทุกเส้นและทุกพื้นที่ ซึ่งเป็นเหตุผลที่ Raspberry Pi ยังตามทัน

ระบบมีตัวติดตามวัตถุในตัว จึงนับคนเดิมซ้ำไม่ได้ และจะไม่นับเมื่อคนเดินมาถึงเส้นแล้วถอยกลับ
หรือเดินเลยปลายเส้นไป

ผลที่ส่งออกเลือกได้: `all` (เข้า/ออก/สุทธิ/รวม), `net`, `in`, `out`, `total`

### รีเซ็ตตัวนับตามกะหรือรายวัน

ตัวนับที่ไม่เคยรีเซ็ตใช้งานไม่ได้จริง เพราะหัวหน้ากะอยากรู้ยอดของกะเมื่อคืน ไม่ใช่ยอดรวมทั้งหมด
ตั้งเวลารีเซ็ตได้ที่ **Runtime → รีเซ็ตตัวนับ**

| โหมด | รีเซ็ตเมื่อไร | ชื่อรอบที่ได้ |
|---|---|---|
| ไม่รีเซ็ต | นับไปจนปิดโปรแกรม | — |
| ตามกะ | ทุกเวลาที่ใส่ในช่อง *เวลาเริ่มกะ* เช่น `06:00, 14:00, 22:00` | `2026-10-10 A` |
| รายวัน | วันละครั้งตามเวลาในช่อง *รีเซ็ตเวลา* | `2026-10-10` |
| รายชั่วโมง | ทุกต้นชั่วโมง | `2026-10-10 15h` |
| ทุก N นาที | ทุก N นาที นับจากเที่ยงคืน | `2026-10-10 15:30` |

กะที่เริ่ม 22:00 และจบ 06:00 จะใช้วันที่ของ**วันที่เริ่มกะ** เพราะเป็นวิธีที่ใบส่งกะหน้างานเขียนไว้

ค่าที่ส่งออกมีสองชุดเสมอ

```json
{"in": 12, "out": 3, "net": 9, "total": 15,
 "period": "2026-10-10 A", "lifetime_in": 1840, "lifetime_out": 1792}
```

`in` / `out` คือยอดของกะนี้ · `lifetime_in` / `lifetime_out` คือยอดรวมตั้งแต่เริ่มติดตั้ง
ซึ่งไม่ถูกรีเซ็ตเลย ทำให้เห็นได้ว่ามีการรีสตาร์ตเกิดขึ้นแทนที่จะเงียบหายไป

เมื่อถึงเวลารีเซ็ต ก่อนที่ตัวนับจะกลับไปเป็นศูนย์ ยอดปิดกะจะถูกส่งออกเป็น event ของตัวเอง

```
topic   tesr/vision/<camera>/event/period_end
```
```json
{"time": "2026-10-10T14:00:01", "camera": "cam1", "event": "period_end",
 "roi": "door_gate", "period": "2026-10-10 A",
 "period_start": "2026-10-10T06:00:00", "period_end": "2026-10-10T14:00:01",
 "in": 12, "out": 3, "net": 9, "total": 15,
 "lifetime_in": 1840, "lifetime_out": 1792}
```

บันทึกเดียวกันนี้จะลงไฟล์ JSONL, CSV และส่งเข้า webhook ด้วย
ทำให้ Flow ใน Node-RED บันทึกยอดเข้ากะที่ถูกต้องได้เลย ไม่ต้องคอยสังเกตว่าตัวนับย้อนกลับเป็นศูนย์

### กันไฟดับ

ใส่ชื่อ **ไฟล์เก็บยอดนับ** เช่น `logs/counters_{camera}.json` ระบบจะเขียนยอดลงดิสก์
แบบปลอดภัย (เขียนไฟล์ชั่วคราวแล้วสลับ) ไม่เกินทุก 5 วินาที และเขียนอีกครั้งตอนปิดโปรแกรม
เมื่อเปิดใหม่

- เปิดใหม่**ในกะเดิม** → นับต่อจากยอดเดิมของกะนั้น
- เปิดใหม่**ข้ามกะไปแล้ว** → กะใหม่เริ่มที่ศูนย์ แต่ยอดรวมทั้งหมดยังอยู่
- ใส่ `--reset-counters` ตอนรัน → ไม่อ่านไฟล์ เริ่มนับใหม่หมด

`{camera}` ในชื่อไฟล์จะถูกแทนด้วย id ของกล้อง หลายกล้องจึงใช้ค่าตั้งเดียวกันได้

ถ้ามีกรณีพิเศษ เช่นสองประตูบนกล้องเดียวกันแต่ทำงานคนละกะ สามารถตั้งทับเฉพาะ ROI นั้นได้
โดยใส่บล็อกเดียวกันลงใน `params.reset` ของ ROI นั้น

```json
"runtime": {
  "counter_reset": {
    "mode": "shift",
    "shifts": ["06:00", "14:00", "22:00"],
    "state_file": "logs/counters_{camera}.json"
  }
}
```

ตั้งชื่อกะเองได้ด้วย ซึ่งอ่านง่ายกว่า A/B/C บน Dashboard

```json
"shifts": [{"at": "08:00", "name": "กะเช้า"}, {"at": "20:00", "name": "กะดึก"}]
```

### นับในพื้นที่

ลากกรอบแล้วปรับจุดให้คลุมพื้นที่ ใช้ปุ่ม `+ จุด` และ `− จุด` เพิ่มหรือลดมุมได้
ตั้ง `จุดอ้างอิงของวัตถุ` เป็น **ขอบล่าง (เท้า)** เมื่อนับคนยืนบนพื้น เพราะกึ่งกลางกล่องอาจอยู่นอกพื้นที่ทั้งที่เท้าอยู่ใน

### ต้องมีไฟล์เพิ่ม

Task กลุ่มนี้ใช้ `tesr_line_engine.py` ต้องวางไว้โฟลเดอร์เดียวกับ `tesr_vision_runner.py`
ถ้าไม่มี ระบบจะแจ้งตอนเริ่มแทนที่จะพังกลางทาง

## 6.8 อ่านป้ายทะเบียน

Task `plate_ocr` คือ OCR ที่บังคับชุดตัวอักษรของป้ายและตรวจรูปแบบป้ายเพิ่มเข้าไป

**ตีกรอบคลุมเฉพาะแถวเลขทะเบียน** ไม่ต้องเอาชื่อจังหวัดเข้ามาในกรอบ
เพราะ `psm 7` อ่านข้อความแบบบรรทัดเดียว และการมีตัวอักษรอีกบรรทัดอยู่ข้างล่าง
เป็นสาเหตุอันดับหนึ่งที่ทำให้อ่านป้ายออกมาเป็นอะไรที่อ่านไม่ได้

สิ่งที่ทำก่อนส่งภาพให้เอนจิน OCR

1. ขยายภาพให้สูงเท่าค่า **ขยายให้สูง** เพราะป้ายทะเบียนในกล้องหน้าประตูมักสูงแค่ 20–40 px
   ซึ่งน้อยกว่าที่ Tesseract ต้องการมาก การขยายก่อนช่วยได้มากกว่าการไปจูนพารามิเตอร์ทีหลัง
2. ลด noise แล้วปรับแสงให้สม่ำเสมอ (CLAHE) ซึ่งช่วยกู้ป้ายที่ภาพหมองหรือโดนเงาครึ่งใบ
3. ทำภาพขาวดำ โดยดูขั้วจากขอบของกรอบ เพราะขอบกรอบป้ายคือพื้นหลัง
   จึงบอกได้ว่านี่คือตัวอักษรเข้มบนป้ายสว่าง หรือกลับกัน

**รูปแบบป้ายคือตัวกันอ่านผิด และเป็นเหตุผลที่ควรใช้ task นี้แทน OCR ธรรมดา**

```json
"params": {"pattern": "^[A-Z]{2}[0-9]{4}$", "min_chars": 4, "max_chars": 12}
```

ค่าที่อ่านได้แล้วไม่ตรงรูปแบบจะ **ไม่ถูกรายงานออกมาเลย**
เพราะเลขทะเบียนผิดที่ไปอยู่ใน log หน้าประตู แย่กว่าการไม่มีเลขทะเบียน
ในกรณีที่รูปแบบชัดเจน ระบบจะลองสลับตัวอักษรที่ OCR มักสับสนทีละตัว
(`O`↔`0`, `I`↔`1`, `S`↔`5`, `B`↔`8`, `Z`↔`2`, `G`↔`6`) และยอมรับเฉพาะเมื่อสลับแล้วตรงรูปแบบ
ถ้าไม่ใส่ `pattern` จะไม่มีการสลับและไม่มีการตรวจรูปแบบ ได้ค่าตามที่อ่านมาตรง ๆ

### ป้ายทะเบียนไทย

ตั้งภาษาอย่างเดียวพอ ที่เหลือตามมาเอง ไม่ต้องพิมพ์พยัญชนะไทยซ้ำในทุก config

```json
"params": {"engine": "tesseract", "lang": "tha+eng",
           "pattern": "^[0-9]?[ก-ฮ]{1,2}[0-9]{1,4}$",
           "min_chars": 3}
```

`lang: "tha+eng"` จะเลือกชุดอักษรไทยให้เอง คือพยัญชนะ 44 ตัวบวกตัวเลข ซึ่งเป็นสิ่งที่อยู่บนแถวทะเบียนจริง
ป้ายไม่มีอักษรละติน ไม่มีสระ ไม่มีวรรณยุกต์ จึงไม่อยู่ในชุดอักษร ถ้าต้องการกำหนดเองก็ยังใส่ `whitelist` ทับได้

**รูปแบบป้าย** ป้ายรถยนต์ส่วนบุคคลคือ ตัวเลขนำหน้า 1 ตัว (มีหรือไม่มีก็ได้) ตามด้วยพยัญชนะไทย 1–2 ตัว
แล้วตามด้วยตัวเลข 1–4 หลักโดยไม่มีศูนย์นำหน้า — `กข 1234` และ `1กข 1234` ถูกต้องทั้งคู่
และ `กข 1` ก็เป็นป้ายที่ถูกต้อง จึงตั้ง `min_chars` เป็น 3
ส่วนป้ายมอเตอร์ไซค์แยกเป็น 3 แถว คือหมวดอักษร ชื่อจังหวัด และตัวเลข
ให้ตีกรอบแยกระหว่างแถวบนกับแถวล่าง อย่าตีกรอบเดียวคร่อมทั้งสองแถว

**ตีกรอบเฉพาะแถวทะเบียน** ชื่อจังหวัดด้านล่างเป็นข้อความอีกบรรทัดหนึ่ง และจะทำให้การอ่านแบบบรรทัดเดียวพัง
ระบบไม่อ่านชื่อจังหวัดโดยตั้งใจ

**เลขไทย** (๐๑๒๓๔๕๖๗๘๙) จะถูกแปลงเป็น 0–9 ก่อนขั้นตอนอื่นทั้งหมด
อันนี้ไม่ใช่การเดาว่าตัวอักษรคืออะไร แต่เป็นตัวเลขเดียวกันที่เขียนอีกแบบ

**พยัญชนะที่สับสนกันได้** จะถูกสลับแล้วลองใหม่เหมือนคู่อักษรละตินด้านบน คือทีละตัว
และยอมรับเฉพาะเมื่อสลับแล้วตรงรูปแบบเท่านั้น รายการที่ให้มาครอบคลุมพยัญชนะที่ต่างกันแค่หัว หาง
หรือเส้นเดียว (`ก`↔`ถ`↔`ภ`, `ค`↔`ด`↔`ต`, `ข`↔`ช`, `บ`↔`ป`, `พ`↔`ฟ`, `ร`↔`ธ`, `ม`↔`น` และอื่น ๆ)
ให้ถือเป็นรายการตั้งต้น เพราะคู่ที่สับสนจริงขึ้นกับฟอนต์บนป้ายและกล้องของคุณ
ควรเพิ่มเองจากที่อ่านผิดหน้างาน

**ต้องลงชุดภาษาบนเครื่องปลายทาง** ขั้นตอนนี้คนลืมบ่อยที่สุด

```bash
sudo apt install tesseract-ocr-tha      # Debian / Raspberry Pi OS
```

หรือตั้ง `"engine": "easyocr"` ซึ่งจะโหลดโมเดลภาษาไทยของตัวเองตอนใช้ครั้งแรก
config เดียวกันใช้ได้กับทั้งสอง engine เพราะ EasyOCR เรียกชื่อภาษาด้วยสองตัวอักษร
ส่วน Tesseract ใช้สามตัวอักษร ระบบแปลง `lang` ให้แล้ว ใส่ `"tha+eng"` ถูกต้องกับทั้งคู่

**ถ้าชุดอักษรไม่ตรงกับที่อ่านได้ ระบบจะไม่เดา แต่จะไม่รายงาน** ถ้าอ่านได้เป็นอักษรไทยแต่ ROI ตั้งเป็นอักษรละติน
ค่าจะถูกระงับและบอกว่าต้องไปแก้ตั้งค่าตัวไหน ถ้าไม่มีการตรวจนี้ อักษรไทยสองตัวจะถูกกรองทิ้ง
แล้วรายงานเฉพาะตัวเลข 4 หลัก ซึ่งดูเหมือนป้ายที่ถูกต้องแต่เป็นของรถคันอื่น
กรณีกลับกันคืออ่านได้อักษรละตินแต่ ROI ตั้งเป็นอักษรไทย ก็ถูกระงับเหมือนกัน

ป้ายอาหรับ รัสเซีย หรือจีน ใช้หลักเดียวกัน คือ `easyocr` หรือ Tesseract ที่ลงภาษานั้นไว้
แล้วใส่ตัวอักษรเหล่านั้นใน `whitelist` มีเฉพาะภาษาไทยที่มีชุดอักษรมาให้ในตัว

ส่วนในเบราว์เซอร์จะดึงข้อมูลภาษาของ Tesseract.js ตามค่า `lang` ที่ตั้งไว้ จึงจูนภาษาไทยในเบราว์เซอร์ได้
แต่ก็ยังเป็นแค่หน้าทดลอง ให้ยืนยันค่าจริงด้วย Python บนเครื่องปลายทาง ที่ซึ่งมีชุดภาษาและกล้องจริง

### ลองใช้

```bash
cd runner
python tesr_vision_runner.py --config ../examples/plate_config.json --once
python tesr_vision_runner.py --config ../examples/plate_config_th.json --once   # ป้ายไทย
```

`examples/plate.jpg` เป็นภาพที่วาดขึ้นเป็นตัวอย่าง ไม่ใช่ภาพถ่ายรถจริง
ส่วน config ป้ายไทยชี้ไปที่กล้องแทนภาพตัวอย่าง เพราะใน repo ไม่มีภาพป้ายไทยให้ ให้ชี้ไปที่หน้างานของคุณเอง

**สิ่งที่ task นี้ไม่ใช่** นี่คือตัว*อ่าน*ป้ายในกรอบที่คุณชี้ไปที่ป้าย ไม่ใช่ระบบ ANPR เต็มรูปแบบ
คือไม่ได้ค้นหาว่าป้ายอยู่ตรงไหนในเฟรมให้ และไม่ได้ติดตามรถข้ามเฟรม
ถ้าเป็นรถที่วิ่งผ่าน ให้ใส่โมเดลตรวจจับที่กล้อง ใช้เส้นนับเป็นตัวบอกว่ารถมาถึงตำแหน่งแล้ว
แล้วอ่านป้ายจาก ROI ที่คลุมตำแหน่งนั้น หรือเทรนโมเดลตรวจจับป้ายแล้วครอปจากกล่องที่ได้

## 7. ปัญหาที่พบบ่อยหน้างาน

| อาการ | สาเหตุที่พบบ่อย | แนวทางแก้ |
|---|---|---|
| ขึ้น `The function is not implemented. Rebuild the library with...` | เครื่องลง `opencv-python-headless` ไว้ ซึ่งไม่มี GUI | ไม่ต้องแก้อะไร ตัว runner ตรวจเจอเอง แจ้งครั้งเดียวแล้วทำงานต่อโดยไม่เปิดหน้าต่าง ค่าที่อ่านได้ยังออกทาง console และทุกช่องทางที่ตั้งไว้ครบ · มีแค่ `--calibrate` ที่ใช้ไม่ได้ ให้ไปจูนในเบราว์เซอร์แทน |
| อ่านได้ `?` บางหลัก | threshold ไม่พอดี หรือกรอบชิดตัวเลขเกินไป | `--calibrate` ปรับ threshold/min_fill, ขยายกรอบให้มีขอบเผื่อ |
| จำนวนหลักไม่ตรง | ช่องไฟระหว่างหลักแคบ ทำให้รวมกัน | ตั้ง `digits` ให้ตรงจำนวนจริง หรือเปลี่ยน `split` เป็น fixed |
| ค่าเปลี่ยนไปมา | แสงกระพริบ / กล้องขยับ | เพิ่ม `stable_frames`, ยึดกล้องให้แน่น, ปิดแสงสะท้อน |
| ป้ายชื่อกรอบทับกันจนอ่านไม่ออก | แก้แล้ว ค่าย้ายไปอยู่กลางกรอบ และสรุปผลอยู่แถบใต้ภาพ | กด `p` เพื่อซ่อน/แสดงแถบสรุป |
| console พิมพ์กระจัดกระจายอ่านยาก | โหมดเดิมพิมพ์ทีละกรอบ | ใช้ `--console summary` (เป็นค่าเริ่มต้นแล้ว) |
| ภาพมืดหรือสะท้อน | มุมกล้องทำมุมกับกระจกหน้าจอ | เอียงกล้อง 10–20°, ใช้ฮูดบังแสง, เลี่ยงไฟส่องตรง |
| FPS ต่ำบน Pi | ความละเอียดกล้องสูงเกินจำเป็น | ลด `width`/`height`, ตั้ง `loop_fps`, ใช้ `every_n_frames` |
| เปิดกล้องในเว็บไม่ได้ | เบราว์เซอร์ไม่ให้สิทธิ์ | ใช้ Chrome หรือ Edge และกดอนุญาตกล้องเมื่อถูกถาม ระหว่างนี้ใช้วิธีโหลดรูปแทนได้ |
| เพิ่มโมเดลแล้วขึ้นว่าโหลดเอนจินไม่ได้ | เครื่องไม่ได้ต่ออินเทอร์เน็ต | เอนจิน ONNX ต้องดึงครั้งแรกครั้งเดียว ต่อเน็ตแล้วเปิดหน้าใหม่อีกครั้ง |
| โมเดลรันได้ในเว็บ แต่ Python บอกหาไฟล์ไม่เจอ | ยังไม่ได้คัดลอกไฟล์ `.onnx` ไป | วางไฟล์ `.onnx` ไว้โฟลเดอร์เดียวกับ `tesr_vision_runner.py` |
| ปุ่มในหน้าเว็บกดไม่ทำงานทั้งหมด | มีสคริปต์ error | หน้าเว็บจะขึ้นแถบแดงบอกข้อความ error ให้เห็น กด F12 → Console เพื่อดูรายละเอียด แล้วแจ้งทีม |

## 8. ข้อจำกัดที่ต้องบอกลูกค้าตรง ๆ

* ความแม่นยำจริงขึ้นกับ **แสง มุมกล้อง ระยะ และความคมชัดของจอเครื่องจักร** ต้องวัดหน้างานเท่านั้น ตัวเลขในเอกสารใด ๆ ก่อนทดสอบถือเป็นค่าประมาณ
* `digits_7seg` ออกแบบมาสำหรับตัวเลขทรง 7-segment ถ้าเป็นฟอนต์ดิจิทัลทั่วไปหรือเข็มอนาล็อก ให้ใช้ `ocr_text` หรือเทรนโมเดลแทน
* ถ้ากล้องถูกขยับหลังติดตั้ง ต้องตีกรอบใหม่ ควรออกแบบขายึดให้ล็อกตำแหน่ง
* การอ่านค่าในเบราว์เซอร์เป็นเพียงตัวช่วยจูน ผลจริงให้ยืนยันด้วย Python บนเครื่องปลายทาง
